# Скетч-студия — как сделать скетч с Ко

Agent-facing. Говори с человеком по-русски, коротко, простыми словами; он не обязан быть программистом. Решения принимает он (4 шага-ворот: шутка, ритм, картинка, музыка); ты предлагаешь, делаешь, проверяешь и показываешь. Прочитай этот файл целиком один раз; перед шагом 5 прочитай ещё четыре справочника: `README.md` скетча (файлы, порядок запуска), docstring `tools/prep.py` (колонки таблиц), ключ `note` в `cues.src.json` (все ключи cue) и `<plugin>/props/README.md` (реквизит и вставки).

Пути: `<plugin>` — папка плагина (`${CLAUDE_PLUGIN_ROOT}`; если пусто — две папки вверх от этого файла; плагин читается из папки без установки — это нормально: задай `export SKIT_STUDIO_ROOT=<эта папка>` один раз, и `paths.sh`/`paths.py` найдут плагин; `new_skit.py` сам записывает путь в `tools/plugin_root.txt`); `<skit>` — папка скетча; `<ws>` — рабочая папка человека. Внутри скетча сначала `source tools/paths.sh` — задаёт `$G` (запуск тяжёлых задач, `tools/run.sh` плагина) и `$PB` (инструменты плагина).

Глоссарий: **ведущий** — модель, которая говорит с человеком (рекомендуется самая сильная, Opus); **исполнитель** — субагент с файлом-заданием (рекомендуется Sonnet, средние усилия), «subagent with a brief file»; **исполнитель M** — отдельный свежий исполнитель для музыки; **Фаза 1 / 2 / M** — разделы `BRIEF.md` скетча. Если субагентов нет, ведущий делает всё сам, по тем же шагам.

**Не Claude Code (Codex и другие; проверено в Codex 18.11 — скетч «Голосовое» за 52 мин).** Плагин тот же, отличаются только инструменты:
- Вызов: человек пишет «хочу скетч» или имя навыка `skit-studio:start`; команды `/skit-studio:…` в тексте ниже = эти навыки.
- Нет `AskUserQuestion` → задай те же вопросы **одним сообщением**, у каждого варианты нумерованным списком; жди ответа. Приложить файл нечем → абсолютный путь или кликабельная ссылка на файл.
- Модели: «Opus» = самая сильная модель хоста, «Sonnet» = его средняя; субагенты хоста (в Codex — `spawn_agent`) с файлом-заданием `BRIEF.md`; нет субагентов — всё сам.
- **Оболочка на Windows:** Codex запускает команды в PowerShell, а голый `bash` оттуда бывает WSL (пути `/mnt/c`, `C:/` не находится). Все `.sh` и `source tools/paths.sh` — только через Git Bash по полному пути из `install.py` (строка `bash`, он же `~/.skit-studio/config.json` → `bash`): `& "C:/Program Files/Git/bin/bash.exe" -lc 'cd "<skit>" && source tools/paths.sh && bash tools/render_draft.sh rhythm'`. Окружение не переживает вызов: `paths.sh`, `export …` и кодировку (`$env:PYTHONIOENCODING='utf-8'` или `python -X utf8`) — в каждом вызове заново.
- Слушать звук ведущий в Codex не может: флаг F0 (шаг 4) и вся музыка — «не проверено на слух», дай человеку послушать нужную реплику на черновике ритма; не пиши «проверено».

Записи, на которых это основано (скетчи 1–3 автора): цифры времени и токенов ниже взяты из скетча 2.

## Первый разговор: установка, пример, три вопроса

Делай это только в начале нового скетча (нет папки скетча). Если человек продолжает существующий — читай его README «Статус» и журнал и иди к нужному шагу.

**1. Установлено ли.** Проверь `~/.skit-studio/config.json` и выполни `python "<plugin>/scripts/install.py"`. Файла нет или в выводе `НЕ ХВАТАЕТ` по node / ffmpeg / pip / gemini → сначала предложи `/skit-studio:setup` одной фразой («Сначала поставлю всё нужное, ≈ 10–15 минут, спрошу один раз»). Нужен ключ Gemini — расскажи, как получить бесплатно (aistudio.google.com/apikey, вход аккаунтом Google, «Create API key»); ключ **не** присылают в чат и не печатают, человек сам вставляет его в файл, который открывает `install.py --key-file` (подробно — `/skit-studio:setup`, раздел 4). В консоли Windows сначала `export PYTHONIOENCODING=utf-8` (иначе кракозябры). Если «НЕТ» только у `playwright` и `hyperframes` — скажи «можно начинать, это поставим позже» (playwright нужен на шаге 9, hyperframes прогреется сам) и не показывай «НЕ ХВАТАЕТ» без этого пояснения. `config.json` нужен только запасному пути `paths.sh`; нет файла — не блокирует (`new_skit.py` пишет `tools/plugin_root.txt`), `install.py` его создаёт.

**2. Пример.** Покажи `<plugin>/examples/ko-skit-example.mp4` (приложи файл; если приложить нечем — дай абсолютный путь и скажи открыть двойным кликом) и скажи одним абзацем: «Вот что получится: вертикальный скетч 35–45 секунд про человека и его ИИ-помощника Ко — настоящая 3D-комната со светом, жесты, голос, при желании музыка, финал 1080×1920. Первый скетч занимает около 4 часов, из них ваши — четыре решения: шутка, ритм, черновик, музыка. Остальное делаю я.»

**3. Три вопроса — одним вызовом AskUserQuestion** (3 вопроса, у каждого 3 варианта; музыку и длину не спрашивай — музыка спрашивается, когда принята картинка (шаг 10), длина следует за шуткой):

```
AskUserQuestion:
 1. Шутка — «Какая у вас шутка?» — «Есть своя» | «Есть тема — предложи 3» | «Удиви меня»
 2. Герой — «Кто герой скетча?» — «Парень по умолчанию» | «Свой по картинке» | «Опишу словами»
 3. Помощник — «Какой помощник?» — «Ко как есть» | «Ко другого цвета/формы» | «Свой по картинке»
```

**Ветвление по ответам:**
- **Таблицу шуток показывай после ответов на все три вопроса и учитывай возраст и роль героя** (дедушка и школьник — другая шутка, чем парень и ноутбук).
- Шутка «Есть своя» → попроси её текстом и проверь по планке шага 1 (5 пунктов); не проходит — скажи, что поправить, и предложи вариант. «Есть тема» → спроси тему и дай таблицу из 3 шуток (шаг 1). «Удиви меня» → 3 шутки на бытовые темы жизни с ИИ (переписка, совет, покупка, рецепт, отчёт) таблицей шага 1.
- Герой «Парень по умолчанию» → шаблонный `guy.json`. «Свой по картинке» → попроси приложить картинку (в CLI — путь к файлу), затем веди по `references/characters.md`. «Опишу словами» → человек описывает (возраст, волосы, борода/усы, одежда, очки, цвета); **до листа одной строкой честно скажи, что из пожеланий паспорт не умеет** (таблица «чего нет» в `references/characters.md`); скопируй `characters/guy.json` в `characters/<имя>.json` (поля и значения — `references/characters.md`), заполни по описанию, выполни из папки скетча `python characters/use.py <имя>.json`, затем `bash tools/snap_sheet.sh hero` (лист: общий план A и крупный B, **субтитры скрыты** — иначе виден демо-текст шаблона, не шутка человека; `snap_sheet.sh` сам вызывает `$G`, оборачивать вручную не надо). Покажи один лист, **под ним честно перечисли, что не получилось**, и спроси «Подходит?».
- Помощник «Ко как есть» → `ko.json`. «Ко другого цвета/формы» → спроси цвет и форму, правь паспорт Ко (`ko_blue_round.json` — образец). «Свой по картинке» → как у героя, паспорт типа `device`.
- Голоса выбирай сам по полу **и возрасту** героя (таблица голосов — шаг 3: молодой — Puck/Fenrir/Leda, пожилой мужчина — Algenib/Sadaltager/Schedar, пожилая — Gacrux/Vindemiatrix; героиня — Kore; Ко всегда `Charon`) и скажи одной строкой: «Голоса: <герой> — <имя>, Ко — Charon; поменять можно». В `voice/style.txt` напиши возраст героя. Дальше — шаги 2 и далее.

## 0. Что это за стиль и почему (не менять без решения человека)

- **Формат:** вертикальное видео 1080×1920, ~35–45 с, 30 fps; одна ночная комната; парень за столом с ноутбуком, Ко (салатовый скруглённый блок, лицо на экране, чёрный контур) на столе; три точки камеры — **A** общий план (оба), **B** парень, **C** Ко — и полнокадровые **INSERT** (экран: чат, редактор). Субтитры шрифтом Impact (`code/assets/fonts/impact.ttf`), показываются и на вставках.
- **Свет = Three.js «глубже»** (`code/look3.js`): мягкие материалы, затенение углов, отражённый свет, свет экрана/неона/Ко, контровой свет, текстуры дерева/ткани/кожи, пост = глубина резкости → bloom → AgX + зерно. Атмосфера `code/atmo.js`: пыль в луче «слегка, не вырви глаз», слабые лучи, мерцание экрана ±4 %, дыхание камеры — каждое выключается одной строкой в `ATMO`. Плоский комикс автор отверг («мягкий, но всё равно не то… свет не тот»).
- **Актёрская игра обязательна:** руки решаются каждый кадр (двухкостные), жесты на реплики, кивки и наклоны головы, настроения на лице. Статичный парень = отклонённый черновик.
- **Ко** сух, вежлив, буквален; его лицо несёт шутки: `normal`, `squint` (косой взгляд), `think` (точки / смотрит вверх), `blink`, `red` (лимит), `stars` (рекламный голос), `happy` (глаза ^ ^, яркий салат + свечение + подпрыгивание).
- **Движок: HyperFrames 0.9.31** (`npx --yes hyperframes@0.9.31 …` везде; версия записана в `<plugin>/tools/hf_version.txt` и `package.json` шаблона — менять только вместе). Three.js r186 лежит в `code/assets/vendor/`.
- **Свой персонаж** вместо парня: раздел «Свой персонаж» ниже.

## 1. Правила для каждого шага

- **Тяжёлое — через `bash $G <команда>`:** любой check / snapshot / render / ffmpeg-пакет / node с браузером. По умолчанию это просто запуск; на слабом ПК (перезагружается или виснет под рендером) человек включает `SKIT_THROTTLE=1` — очередь, разнесённый старт, рендер в 2 потока. Рендеры — `--workers 2`, в фоне, не больше одного своего рендера одновременно, исполнителей одновременно не больше 4.
- Всё в `code/` — чистая функция от t (перемотка безопасна, всё с seed). Данные скетча живут только в `timeline.json` (из `prep.py`) и `cues.src.json` → `cues.json` / `code/cues.js`. Никогда не пиши времена скетча числами в `index.html`.
- Времена cue **относительные к реплике** (`L3.s+0.2`, `S5.e-0.1`) — смена пауз потом не ломает жесты.
- **Никогда не удаляй файлы человека.** Старые рендеры и неиспользованные варианты переноси в `<skit>/old/` (с тем же относительным путём).
- «Принято» — только когда человек сказал это явно. Запиши его слова дословно в README скетча, раздел «Статус». Совет агента — не решение.
- Субтитры берутся из утверждённого текста скрипта (`LINES` в `prep.py`), никогда из слов Whisper.
- Любой `open()` JSON/текста с кириллицей — `encoding='utf-8'`.
- Ведущий — сильная модель (сценарий, паузы, проверка кадров, разговор с человеком); исполнители — Sonnet со средними усилиями и файлом-заданием. Контекст ведущего к финалу вырастает до ~250k токенов — если он за ~180k, начни финал в свежей сессии.
- Скриншоты/листы: смотри не больше 3 за раз, в масштабе 0.4.

## 2. Начало нового скетча

```bash
python "<plugin>/scripts/new_skit.py" <имя-скетча> --dir <ws>
```
Копирует шаблон (комната, парень, Ко, свет, пылинки, руки, фокус, свечение), `tools/plugin_root.txt` и музыкальные помощники. `<имя>` может быть с пробелами и кириллицей. Вывод скриптов всегда UTF-8 (если в консоли Windows всё равно кракозябры — `PYTHONIOENCODING=utf-8`; смотри файлы, а не консоль).

**Шаблон не пустой — в нём демо.** Что демо и что делать:
- `voice/take1.wav`, `voice/take1.words.json` — демо-дубль (3 реплики): `new_skit.py` сам убирает их в `old/demo/` (флаг `--keep-demo` оставляет). Твой дубль на шагах 3–4 пишется на их место.
- `voice/dialog.txt`, `voice/style.txt` — демо-тексты про парня и знакомства: **перепиши целиком** под героя, его пол и тему.
- `tools/prep.py`: `LINES`, `SHOTS`, `KO`, `EVENTS`, `TAIL` — демо-таблицы: **замени своими** (шаг 5); остальной код не трогай.
- `cues.src.json`: демо-жесты, настроения, `typing`, `clock`, `headphones` — **замени** (шаг 6); ключ `note` оставь.
- Производные (`voice/voice.wav`, `voice/envelope.json`, `timeline.json`, `cues.json`, `code/data.js`, `code/cues.js`, `code/assets/voice.wav`) перезапишутся `prep.py` → `cues.py` → `mix.py`; руками не правь. Эти три скрипта обязательны и для черновика ритма.
- Остальное (`code/`, `tools/`, `props/`, `characters/`) — код: оставь. Проверь, что шаблон запускается, до любых правок: `cd <skit>/code && bash $G npx --yes hyperframes@0.9.31 check` → 0 ошибок (первый запуск после установки ≈ 40 с: HyperFrames прогревается сам, отдельная установка не нужна; `playwright` на шагах 1–8 не нужен — только для проверок шага 9). Внешний `gpu.sh` ≠ `$G`: у тебя `$G` = `tools/run.sh` плагина. README в папке — описание шаблона, не скетча: **перепиши его целиком** (по-русски): идея, «Что здесь», «Статус». Веди журнал шагов (шаг · минуты · токены · что дал человек) — он нужен для следующих скетчей.

### Шаг 1 — таблица сценария

Предложи человеку 2–3 шутки таблицей, в каждой: `# · план (A/B/C/INSERT + лицо Ко) · реплика / действие`, ~10–18 реплик, **не больше 70 слов** суммарно (скетч 2: 63 слова → дубль 29.2 с при ≈ 2.2 слова/с → 39.5 с после пауз; паузы добавляют ≈ 35 %). Хорошая шутка Ко: узнаваемая ситуация жизни с ИИ, Ко отвечает буквально и сухо, поворот в последней трети, финальный образ (лицо Ко + парень «сдулся»). Любой новый реквизит или вставку назови в таблице — каждый стоит ≈ 30 мин работы исполнителя. Планка для каждой шутки: (1) предпосылка ясна к реплике 2; (2) поворот в последней трети переосмысляет сказанное раньше; (3) последняя реплика Ко — кульминация, короткая (≤ 5 слов); (4) есть финальный образ; (5) ≤ 70 слов. Жди выбора человека. Разобранный пример — скетч 2 «Плюс один» — Приложение A.

### Шаг 2 — тексты для голоса

`voice/dialog.txt`: одна строка на реплику дубля, `Guy: …` / `Ko: …` (имена должны совпасть с `--speakers`). Числа пиши словами, «AI» как «эй-ай» (субтитры оставляют «AI»). `voice/style.txt` (шаблонный — про парня и знакомства, перепиши под героя и его пол): один абзац режиссёрской заметки по-русски — обстановка (поздняя ночь, тихая комната), манера каждого (Guy: молодой, эмоции меняются по ходу; Ko: спокойный, сухой, вежливый, лёгкая ирония) и пометки для 3–5 ключевых реплик («с маленькой паузой на тире»). Не оставляй реплики парня оборванными, если смысл зависит от продолжения («Откуда ты…» прозвучало как «where are you from» → «Откуда ты знаешь?»).

### Шаг 5 — таблицы `tools/prep.py` (здесь живёт комедия)

Числа слов бери из `words.py` (шаг 4), не считай на глаз. `LINES = [(speaker, утверждённый текст субтитра, число слов Whisper, пауза ПЕРЕД репликой или None)]`. Скрипт проверяет, что числа слов в сумме равны общему числу слов Whisper — чини числа, не assert. Он режет границу каждой реплики в самой длинной тишине рядом (Whisper идёт ~0.2 с раньше), расставляет реплики с твоими паузами (`MIN_GAP` 0.12 с), добавляет `TAIL` после последней и пишет `voice/voice.wav`, `timeline.json`, `voice/envelope.json` (рот), `code/data.js`, `code/assets/voice.wav`.

Правила комического тайминга (из двух принятых скетчей; значения скетча 2 в скобках):
- **Пауза перед кульминацией:** 0.8–1.2 с тишины перед репликой, которая попадает («Пишу: …» 0.8, «…Она тоже через AI?» 1.2). Быстрый обмен в остальном: 0.25–0.45 с («Вы?» 0.25 → «Мы.» 0.3).
- **Разрезай реплику дубля, чтобы вставить паузу внутрь:** одна реплика дубля может стать несколькими строками субтитров (числа слов), у каждой своя пауза — «Она ответила за две секунды.» | 0.4 | «С длинным тире.»
- **Дай картинке осесть:** вставка получает свои секунды без речи (вставка чата 2.7 с, следующая реплика через 3.15 с); реплику можно произнести поверх вставки (L8 поверх зума на тире).
- **Медленный наезд на осознание:** план с «доходит до героя» получает `push` (величина наезда) + `ease` (>1 = медленный старт) в extras `shot_starts`.
- **Хвост:** ≈ 2 с финального общего плана после последней реплики для финального образа (Ко happy со свечением, парень оседает).
- Резать на реплике: план реакции начинается в начале реплики, состояние лица Ко — за ~0.1–0.3 с до его реплики.

Остальные три таблицы — функции от `(s, e, D)`, где `s(i)` / `e(i)` = начало/конец реплики i (с 1), `D` = длительность: `SHOTS` → строки `(id, cam, start, extra)`, cam `A|B|C|INSERT`, extra `ins` (имя вставки), `push`, `ease`; `KO` → `{state, start, end}`; `EVENTS` → `{type, start, …доп. времена}` для вставок/реквизита (напр. `chat1` с `sent`, `reply`). Полное описание колонок — docstring `prep.py`; таблицы скетча 2 в его комментариях как разобранный пример. `prep.py` ещё переписывает `data-duration` в `index.html`. Напечатай таблицу планов и один раз сверь со сценарием. Полный `LINES` скетча 2 с паузами — Приложение A; для похожих ритмов начинай с этих значений.

### Шаг 6 — cue: `cues.src.json` → `python tools/cues.py`

Порядок запуска при любом изменении: `prep.py` → `cues.py` → `sound/mix.py` (`mix.py` печатает `preview peak … / … LUFS` — это норма, не ошибка). Для черновика ритма достаточно выставить `clock`/`headphones`, убрать демо-жесты и настроения; `BRIEF.md` нужен, только если работает исполнитель. Грамматика времени: секунды, `L3.s+0.2` / `S5.e-0.1` (начало/конец реплики / плана + сдвиг), или ссылка на событие `chat1.reply+0.1` (тип строки `EVENTS` + поле). Ключ `note` в `cues.src.json` описывает каждый ключ. Ключи (жест задаёт `dur` или `end`):
- `gestures`: `{t, dur|end, who: guy|ko, type, side?: L|R, amp?}`. Типы парня: `palm`, `point`, `stop`, `finger_up`, `hands_up`, `shrug`, `rub_eyes`, `nod`, `tilt`, `shake`, `lean`, `sink`, `jerk` (+ позы реквизита, напр. телефон `show_phone`). Ко: `tilt`, `lean` (`amp: -1` = откинуться, гордый). R = рука ближе к Ко, L = дальше (рука с телефоном).
- `moods`: `{start, end, by (y бровей), tilt (наклон бровей), lid (0..1 открытость), lean, smile}` — сглаживается 0.2 с; вне записей = нейтрально.
- `look`: `{start, end, at: screen|ko|<цель реквизита>, out?}`; по умолчанию = Ко; печатая, смотрит на экран.
- `ko_look`: `{start, end, lx, ly}` смещение глаз Ко (косой взгляд на реквизит).
- `typing` (времена `keys`), `enter`, `clock` (текст), `limit`, `sparkle`, `sfx`: звук и мелкие эффекты.

**Время суток и свет.** `clock` — только текст на часах в комнате; освещение комнаты — ночное и зашито в `code/look3.js`. Шутка про утро или день с часами `06:15` всё равно будет в ночной комнате: либо выбери ночной повод (или оправдай в сценарии: «ещё темно»), либо отдельно закажи смену света (≈ 30–60 мин исполнителя, новый лист-образец света для человека).

Задание исполнителю: скопируй в `BRIEF.md` скетча структуру: «Где что лежит» (что ведущий уже сделал), «Правила (все фазы)» (`$G`, версия HyperFrames, чистая f(t), не удалять, пределы чтения, отчёт ≤ 120 слов), «Фаза 1 — черновик ритма» (его файлы, пронумерованные задачи, проверка + лист + рендер + postcheck), «Фаза 2 — полный черновик» (жесты/настроения/реквизит по реплике в грамматике cue, проверки шага 9), позже «Фаза M». В каждой фазе перечисли файлы, которыми исполнитель владеет.

Гид по игре: на каждую реплику парня — минимум движение головы (кивок/наклон) и один жест рукой или телом на ключевом слове; Ко получает наклон/откидывание на 2–3 ключевых репликах и состояние лица на каждом ударе шутки; реплика-поворот получает `sink` или `jerk`; настроения меняются с эмоцией каждой реплики парня (воодушевлён → хмурится → озадачен → доходит → потрясён → сдулся в скетче 2). На 18 реплик хватило 16 жестов + 7 настроений.

### Шаг 11 — финал

`bash tools/final.sh <имя> <утверждённое-превью.mp4> <принятый-черновик.mp4>` в фоне (без музыки — принятый черновик в обоих аргументах): `render_ss.py code … --portrait --workers 2` (2160×3840 → 1080×1920, ≈ 4 мин), звук утверждённого превью **как есть** (`-c copy`, то, что слышал человек), ebur128 (≈ −14 LUFS, пик ≤ −0.5 dBFS), postcheck, `render_diff` против принятого черновика. Норма = худшая ячейка ≤ 8 И каждая ячейка выше порога 6 лежит на тексте субтитра или краю свечения (сглаживание 4K); всё остальное (область, форма, цвет) → исправить до показа. `final.sh` сам проверяет «худшая ≤ 8» (полный вывод — `snaps/<имя>-diff.txt`) и при провале выходит с ошибкой и строкой `FAIL`; postcheck сравнивает со снимками **принятого** черновика (`snaps/<черновик>-post`). Затем уборка: оставь финал, принятый черновик, черновик ритма, утверждённое музыкальное превью; всё остальное → `<skit>/old/`. README «Статус» со словами принятия человеком; по строке на шаг в журнале шагов.

## 7. Сообщения человеку (по-русски, коротко; отправляй файл вложением)
